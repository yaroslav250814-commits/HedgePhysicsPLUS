# Настройка персонажа и приёмов

Возможности игры включаются в C#, а числовые параметры каждого персонажа сохраняются в prefab через приватные `[SerializeField]` поля. Публичные свойства позволяют менять те же параметры из кода. Стартовые значения текущей игры сохранены.

## Отключение приёмов в коде

Текущие настройки: DropDash включён; DropDashAirDash, DropDashHomingAttack, BoostedHomingRebound и ReboundRestoresAirAbilities выключены. Зарядка и наземный запуск Drop Dash работают без дополнительных воздушных приёмов.

Откройте `Assets/GameplayScripts/PlayerAbilityFeatures.cs`. У нужного переключателя замените `true` на `false` и дождитесь компиляции Unity. Эти переключатели общие для всей игры; в Inspector их нет.

| Переключатель | Что отключает значение `false` |
|---|---|
| `Jump` | Обычный прыжок с земли |
| `ManualRolling` | Включение и отмену качения кнопкой Roll; клубок Spin Dash и Drop Dash остаётся |
| `SpinDash` | Наземный Spin Dash |
| `HomingAttack` | Наведение на цель, включая усиленный вариант; обычный рывок без цели остаётся |
| `AirDash` | Рывки без цели, включая усиленный; наведение на цель остаётся |
| `DropDash` | Drop Dash и его дополнительные воздушные атаки |
| `DropDashAirDash` | Только усиленный рывок без цели после отпускания Drop Dash |
| `DropDashHomingAttack` | Только усиленный Homing Attack после отпускания Drop Dash |
| `BoostedHomingRebound` | Рывок вверх после успешного усиленного Homing Attack |
| `ReboundRestoresAirAbilities` | Немедленное восстановление воздушных способностей при отскоке; сам отскок остаётся |

Например, для Drop Dash с запуском по земле и падением клубком, без дополнительных воздушных приёмов, измените в этом файле четыре строки:

```csharp
public static bool DropDashAirDash = false;
public static bool DropDashHomingAttack = false;
public static bool BoostedHomingRebound = false;
public static bool ReboundRestoresAirAbilities = false;
```

Обычные Spin Dash, Homing Attack и воздушный рывок при этом сохраняются. Если отключённый усиленный приём не выполняется, Соник продолжает падение клубком; заряд и доступный воздушный рывок не расходуются. Отключение сброса способностей не отменяет обычное восстановление при приземлении и возрождении и обычную перезарядку Homing Attack.

## Постепенный заряд Drop Dash

Компонент `Action06_DropDash` находится на объекте игрока. Сила накапливается при удержании кнопки: `заряд += ChargeSpeed × Time.fixedDeltaTime`, до `MaximumCharge`. Минимальный порог задаёт `MinimumCharge`. Запуск использует накопленную силу; частичный заряд слабее полного.

| Свойство / поле Inspector | Назначение | Текущий персонаж |
|---|---|---|
| `ChargeSpeed` / Charge Speed | Сила заряда за секунду | ≈514,286 |
| `MaximumCharge` / Maximum Charge | Максимальная накопленная сила | 180 |
| `MinimumCharge` / Minimum Charge | Порог запуска и воздушного приёма | 40 |
| `BoostInputWindow` / Boost Input Window | Окно прыжка после отпускания, секунды | 0,2 |
| `LandingSpeedMultiplier` | Множитель силы запуска по земле | 1 |
| `AirDashSpeedMultiplier` | Множитель силы воздушного рывка | 1 |
| `HomingSpeedMultiplier` | Множитель силы усиленного Homing Attack | 1 |
| `LaunchAfterRelease` | Сохранить наземный запуск после отпускания кнопки | Выключен |
| `LandingDustCount` | Число частиц при наземном запуске | 8 |

Сейчас максимальная сила соответствует прежнему полному Spin Dash — 180; до неё заряд доходит за 0,35 секунды. Эти параметры независимы от наземного Spin Dash: изменение его максимума больше не меняет Drop Dash автоматически. `ChargeDuration` оставлен как совместимое C#-свойство: чтение возвращает `MaximumCharge / ChargeSpeed`, запись пересчитывает скорость заряда. `Charge` показывает текущую силу, `HasCharge` — достижение минимального порога, `Charged` — достижение максимума.

Например, в `Start` своего компонента на игроке можно задать:

```csharp
var dropDash = GetComponent<Action06_DropDash>();
dropDash.MaximumCharge = 180f;
dropDash.MinimumCharge = 40f;
dropDash.ChargeSpeed = 360f; // Полный заряд за 0,5 секунды.
dropDash.BoostInputWindow = 0.25f;
```

Частичный воздушный приём использует накопленную силу с соответствующим множителем, но не замедляет атаку ниже обычной скорости Air Dash / Homing Attack. Короткое нажатие ниже минимального порога оставляет Соника клубком без запуска. Отпускание замораживает накопленный заряд. Пауза его сохраняет, урон и смерть отменяют.

## Остальные параметры

| Компонент | Что настраивается |
|---|---|
| `PlayerBhysics` | Ускорение, обычная и предельная скорость, замедление, управление в воздухе, гравитация и предел падения, прилипание к поверхности, склоны, приземление и качение |
| `PlayerBinput` | Чувствительность поворота, альтернативная модель управления и её интенсивность |
| `Action01_Jump` | Сила и длительность удержания прыжка, выход с поверхности, влияние склона, торможение после отпускания, задержка воздушной атаки |
| `Action02_Homing` | Скорость homing и рывка, учёт текущего импульса, допустимое направление цели, число рывков за полёт, сила отскока и сохранение горизонтального импульса |
| `HomingAttackControl` | Поиск цели и число физических шагов перезарядки homing |
| `Action03_SpinDash` | Скорость набора, минимальный и максимальный заряд, торможение при зарядке, анимация клубка, частицы и тряска камеры |
| `TechniqueChain` | Время между победами в комбо и отображение счётчика с полоской времени |

Для двух свободных рывков задайте `GetComponent<Action02_Homing>().AirDashesPerFlight = 2`. Ноль запрещает свободные рывки, не запрещая наведение на цель. Перезарядка, зарядка Drop Dash и исчезновение цели не создают дополнительные использования.

`ReboundHorizontalRetention` задаёт сохраняемую долю горизонтального импульса при отскоке: 0 — только вверх, 1 — сохранить весь. `RequireJumpForRebound` по умолчанию включён; выключение позволяет отскакивать автоматически, если сам приём разрешён переключателем C#.

У старой физики сохранены единицы: `SpinDashChargingSpeed` добавляет заряд за физический шаг, `HomingTimerLimit` и `CooldownSteps` считаются шагами. `Gravity` задаёт прибавку скорости за шаг. Новый `Drop Dash.ChargeSpeed` считается за секунду. Подсказки Inspector указывают единицы; изменение частоты физики меняет поведение старых покадровых параметров.

Изменение стартового значения `[SerializeField]` в исходнике не заменяет уже сохранённое значение prefab. Для существующего персонажа используйте Inspector, prefab override или присвойте публичное свойство из C#. Свойства ограничивают недопустимые значения, например нулевые делители физики и отрицательные пределы заряда.

## Комбо по времени

`GetComponent<TechniqueChain>().ComboWindowSeconds = 5f` задаёт окно между победами. Новая длительность применяется при следующем уничтожении врага. `RemainingSeconds` и `RemainingFraction` позволяют сделать собственный интерфейс; `ShowTimer = false` скрывает встроенный счётчик, сохраняя логику комбо. Компонент установлен на prefab и в игровых сценах, поэтому приватные поля доступны в Inspector. Все уникальные уничтожения врагов продолжают цепочку независимо от атаки и приземления. При тайм-ауте или финише выдаётся высший бонус, при уроне или смерти незавершённый бонус отменяется. Пауза останавливает отсчёт.

## Проверка изменений

Старые имена полей перенесены через `FormerlySerializedAs`; исходные prefab, сцены и скрипты сохранены в `Migration/Customization/Before`. Отчёт `serialization-report.txt` сравнивает старые параметры до и после переноса. Проверки `CustomizationTools.Stage00` и `.Altitude` проверяют переключатели через настоящий ввод, частичный заряд и запуск, независимые множители, число рывков и сохранение полей Unity. Дополнительно используются проверки Drop Dash, Homing Attack и движения.
